# 本地运行与进程管理（PM2）

> 目的：本机开发时**不弹黑窗口**、进程崩溃自动重启、日志集中且自动轮转。
> 适用范围：开发机（Windows）；生产用 `docker compose`，见 `doc/10-上线部署手册.md`。

## 1. 为什么用 PM2

| 问题（直接用命令行起服务） | PM2 后 |
| --- | --- |
| 每个服务一个 cmd 窗口，抢焦点、任务栏堆积 | 全部后台守护进程，**0 窗口** |
| 误关窗口 = 服务停止 | 只能 `pm2 stop`，不会误关 |
| 崩了不重启，页面直接 502 | 自动重启（api 最多 10 次，间隔 2s） |
| 日志散落在多个 `.dev/*.log` | 统一到 `.dev/pm2/`，带时间戳 + 自动轮转 |
| 不知道谁占着端口 | `pm2 list` 一眼看到 pid / 内存 / 重启次数 |

## 2. 首次启动

```bash
# 1) 数据库（嵌入式 PostgreSQL，端口 5433）
npm run db:local
#    建议在自己的终端里前台运行（Ctrl+C 停，数据在 .dev/pgdata）
#    不想开窗口的启动方式（Windows）：
#    powershell -Command "Start-Process node -ArgumentList 'scripts/dev-db.mjs' -WindowStyle Hidden"

# 2) 三个服务（后台，无窗口）
npx pm2 start ecosystem.config.cjs
```

启动后自检：

```bash
npm run verify     # 200ms 内检查 db/api/web/admin 四个服务
npx pm2 list       # 三个进程应为 online
```

| 服务 | 端口 | 启动方式 |
| --- | --- | --- |
| api | 8080 | `node server/dist/main.js` |
| web | 3000 | `next start -p 3000` |
| admin | 3001 | `next start -p 3001` |

> PM2 运行的是**构建产物**。改了后端需 `npm run build -w @quizpeak/server` 再 `pm2 restart api`；改了前端需 `npm run build -w @quizpeak/web-pc`（或 `admin`）再 `pm2 restart web`。
> 想改完立即生效、不构建 → 用 `npm run dev:all`（watch + HMR，前台一个窗口）。

## 3. 日常命令

| 场景 | 命令 |
| --- | --- |
| 看状态 | `npx pm2 list` |
| 看 API 日志 | `npx pm2 logs api`（Ctrl+C 只退出查看，不停服务） |
| 只看最近 200 行 | `npx pm2 logs api --lines 200 --nostream` |
| 重启单个服务 | `npx pm2 restart api` / `restart web` / `restart admin` |
| 全部重启 | `npx pm2 restart all` |
| 停止全部 | `npx pm2 stop all` |
| 重新启动 | `npx pm2 start ecosystem.config.cjs` |
| 从列表移除 | `npx pm2 delete all` |
| 资源监控 | `npx pm2 monit` |
| 保存当前进程列表 | `npx pm2 save` |

> `pm2` 装在项目 `devDependencies`，统一用 `npx pm2` 调用，不影响全局环境。

## 4. 日志与轮转

| 项 | 值 |
| --- | --- |
| 输出目录 | `.dev/pm2/` |
| 文件 | `api-out.log` / `api-err.log`、`web-*.log`、`admin-*.log` |
| 行首时间戳 | 已开启（`time: true`） |
| 单文件上限 | **10MB**（超出即切分） |
| 保留份数 | **7 份** |
| 压缩 | **开启**（切分后的历史日志为 `.gz`） |
| 定时切分 | 每天 00:00（`rotateInterval: 0 0 * * *`） |
| 检查间隔 | 每 30 秒（`workerInterval: 30`） |

查看当前配置：

```bash
npx pm2 conf pm2-logrotate
npx pm2 list            # 应能看到 pm2-logrotate 模块 online
```

手动清理历史日志：

```bash
npx pm2 flush               # 清空所有日志内容（不删文件）
# 或删除切分后的归档
rm -rf .dev/pm2/*.gz
```

## 5. 数据库单独管理（为什么不交给 PM2）

嵌入式 PostgreSQL 通过 `scripts/dev-db.mjs` 启动，**收到停止信号时会做优雅关闭**。交给 PM2 后，`pm2 stop` 在超时后会强杀，存在数据文件异常的风险，因此保持独立：

```bash
npm run db:local          # 前台运行（推荐，Ctrl+C 优雅停止）
```

数据目录 `.dev/pgdata`（已 gitignore），重启机器后再执行一次即可，数据不会丢。

## 6. 常见故障处理

| 现象 | 处理 |
| --- | --- |
| `/api/health` 返回 `db: down` | 数据库没起：`npm run db:local`，再 `npx pm2 restart api` |
| 页面 502 / 打不开 | `npx pm2 list` 看是否 errored；`npx pm2 logs web --lines 100 --nostream` 看原因 |
| 端口被占用（EADDRINUSE） | `Get-NetTCPConnection -LocalPort 3000 -State Listen` 找 PID 后 `Stop-Process -Id <pid> -Force`，再 `pm2 restart web` |
| 改了代码没变化 | 忘记重新 build：先 build 再 `pm2 restart`；或改用 `npm run dev:all` |
| 进程反复重启（↺ 次数飙升） | 看重启次数与日志尾部：`npx pm2 logs api --lines 50` |
| 想彻底重来 | `npx pm2 delete all` → `npm run verify` 确认端口空了 → 重新 `pm2 start` |

## 7. 开机自启（可选）

PM2 的 `pm2 startup` 在 Windows 不支持，需借助任务计划程序：

1. 打开「任务计划程序」→ 创建基本任务
2. 触发器：登录时
3. 操作：启动程序
   - 程序：`C:\Windows\System32\cmd.exe`
   - 参数：`/c "cd /d D:\yiyi\dati && npx pm2 resurrect"`
4. 首次需先执行一次 `npx pm2 save`（保存当前进程列表）

> 数据库不会随 PM2 自启，需另建一条任务执行 `node scripts/dev-db.mjs`，并按第 5 节的理由接受其窗口或改用隐藏参数。

## 8. 与生产的关系

| | 本地（PM2） | 生产（Docker compose） |
| --- | --- | --- |
| 进程管理 | PM2 | Docker restart policy |
| 前端 | `next start`（构建产物） | Next standalone 镜像 |
| 数据库 | 嵌入式 PG（5433） | postgres 容器（5432，不对外） |
| 反代与 HTTPS | 无（直连端口） | nginx + TLS |
| 日志 | `.dev/pm2/*.log` + 轮转 | `docker compose logs`（可加 max-size） |

两边共用同一份代码与 `packages/shared`，只有运行方式不同。
