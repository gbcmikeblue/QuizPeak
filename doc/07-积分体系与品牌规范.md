# 07 · 积分体系与品牌规范

> 需求变更（2026-10-22）：品牌由 Quizix 改为 **知巅 / QuizPeak**；经济模型由「金币充值+提现」整体替换为 **纯站内积分**，不涉及任何货币、支付、提现。本文为准，与 `01`/`02` 中旧钱包章节冲突时以本文为准。

## 1. 品牌

| 项 | 值 |
| --- | --- |
| 中文名 | 知巅 |
| 英文名 | QuizPeak |
| 标识 slug | `quizpeak`（包 scope `@quizpeak/*`、JWT issuer、存储 key、容器名、数据库名） |
| Slogan | 中文「答题登顶，积分上榜」／英文「Answer. Climb. Top the board.」 |

命名口径：
- 中文界面一律用「知巅」，英文界面用「QuizPeak」，不再出现 Quizix。

**文案禁用词**（避免被判为有奖竞赛/涉赌类）：金币、充值、提现、现金、红包、奖池、开奖、押注、赔率、赚钱、返现；Coins、Cash、Withdraw、Bet、Prize Pool。
统一替换为：积分、赚积分、名次奖励、积分榜、上榜、点赞。

## 2. 积分定位

- 积分是**站内虚拟权益凭证**，只能用于站内答题/竞赛消耗，**不可购买、不可转让、不可兑换任何货币或实物**。
- 积分不设「充值」入口；获取全部来自行为激励（签到、活动、点赞、看广告）。
- 新用户注册即赠 100 积分，用于体验付费题库。

## 3. 积分获取

| 方式 | 默认值 | 频次限制 | 实现 |
| --- | --- | --- | --- |
| 每日签到 | 基础 +10；连续签到每天 +2，递增封顶 +20（即第 11 天起每天 +30） | 每日 1 次 | `POST /points/checkin`，按 `Asia/Shanghai` 自然日 + 连续天数判断 |
| 看广告得积分 | 每次 +10 | 每日 5 次 | `POST /points/ad-reward`，需接入激励视频 SDK 回调后发放 |
| 给上榜选手点赞 | 每次 +5（给点赞者）；被点赞者人气 +1 | 每日 5 次，同一选手每日仅 1 次 | `POST /points/like`，`fromUserId+toUserId+日期` 唯一 |
| 活动送积分 | 活动配置（示例 +50） | 每活动每人 1 次 | `POST /points/activities/:id/claim` |
| 新人礼 | +100 | 每人 1 次 | 注册时自动发放 |
| 邀请奖励 | +100（给邀请人） | 被邀请人通过首个关卡后触发 | 待答题引擎接入 |
| 答题/竞赛奖励 | 按题库与名次配置 | — | 答题引擎 / 竞赛结算 |

签到积分公式：`基础分 + min((连续天数-1) × 递增步长, 递增封顶)`。
断签（昨日未签到）后连续天数归 1。

## 4. 积分消耗

| 场景 | 说明 |
| --- | --- |
| 解锁付费 Quiz | 卡片 `解锁消耗 N 积分`，一次解锁 7 天内可重玩（`ENROLL_VALID_DAYS`） |
| 竞赛报名 | 竞赛 `entryFee`（积分），报名费为 0 则免费 |
| 提示 Hint | 每场免费 1 次，超出扣 10 积分 |
| 其他站内权益 | 后续可扩展（头像框、徽章皮肤等，均不涉及货币） |

积分不足时统一返回 400 + `积分不足`，前端引导「赚积分」页（签到/看广告/点赞/活动）。

## 5. 数据模型（`server/prisma/schema.prisma`）

| 表 | 说明 |
| --- | --- |
| `User.points` / `totalEarned` / `likesReceived` | 当前积分、历史累计获得、被点赞人气 |
| `PointTransaction` | 积分流水：`change`、`balanceAfter`、`type`、`refType`、`refId`、`remark`；`(type, refType, refId)` 唯一保证幂等 |
| `DailyCheckin` | `(userId, checkinDate)` 唯一，记录连续天数与本次积分 |
| `AdView` | `(userId, viewDate, seq)` 唯一，控制每日次数 |
| `PointLike` | `(fromUserId, toUserId, likeDate)` 唯一，防重复点赞刷分 |
| `Activity` / `ActivityReward` | 活动配置与领取记录（每人每活动一次） |

已删除：`CoinPackage`、`PayOrder`、`WithdrawOrder` 及支付/提现枚举。**系统内不存在任何支付记录表**。

一致性：所有积分变动只能走 `PointsService.change()` / `applyChange(tx)`，条件更新（`where: { points: 旧值 }`）防并发超扣，流水与余额快照同事务写入。

## 6. 接口

```
GET  /api/points/summary                 余额、今日获得、签到状态、任务进度（含剩余次数）
GET  /api/points/transactions?page=      积分流水
GET  /api/points/activities              进行中的活动
POST /api/points/checkin                 签到
POST /api/points/ad-reward               看广告领积分
POST /api/points/like {toUserId}         给上榜选手点赞
POST /api/points/activities/:id/claim    领取活动积分
```

## 7. 页面

| 端 | 页面 | 说明 |
| --- | --- | --- |
| 用户端 | 顶部积分胶囊 | 显示当前积分，点击进「赚积分」 |
| 用户端 | 赚积分中心 `/points` | 任务卡（签到/广告/点赞/活动）+ 今日进度 + 连续签到天数；替代原「购买金币」 |
| 用户端 | 积分明细 `/points/history` | 按类型/时间筛选，展示 +/− 与余额 |
| 用户端 | 排行榜 `Top Players` | 每行「点赞」按钮，点击 +5 积分（受日限次），展示人气值 |
| 后台 | 积分流水 `/dashboard/points` | 全站流水、筛选、导出、人工调整（填理由） |
| 后台 | 积分任务 `/dashboard/tasks` | 配置签到/广告/点赞/活动的积分值与次数 |

文案规范：一律称「积分」，不出现「金币/充值/提现/奖池」。

## 8. 合规

- 不设充值、不设提现、不设现金等价物 → 不构成支付业务，也避免「双向兑换」类风险。
- 广告需接入合规激励视频（腾讯优量汇 / 穿山甲等），发放前校验 SDK 回调签名与 `transId` 唯一，防伪造回调刷分。
- 未成年人：积分不可变现，风险低；仍建议在协议中声明积分不可转让、不可兑现、平台可依规调整。
- 小程序类目建议「教育服务-在线教育」或「知识问答」，名称「知巅」不含敏感词。

## 9. 已确认的规则

| # | 规则 | 值 |
| --- | --- | --- |
| 1 | 签到 | 每日 1 次，+10 起，连续每日 +2，封顶 +20 递增 |
| 2 | 广告 | 每次 +10，每日 5 次 |
| 3 | 点赞 | 每次 +5，每日 5 次，同一选手每日 1 次，不能给自己点赞 |
| 4 | 活动 | 每人每活动 1 次，按活动配置积分 |
| 5 | 新人礼 | 注册 +100 |
| 6 | 解锁 Quiz | 扣题库配置积分，7 天有效 |
| 7 | 所有数值 | 存 `site_config`，后台可改，60 秒内生效 |
