### 1.1 截图带来的需求修正（已回写文档）

| # | 原判断 | 截图实证 | 处理 |
| --- | --- | --- | --- |
| 1 | 计时可能是整卷总时长 | 答题页显示单题倒计时 `01:58`，且 `8 题 × 120s = 16:00`、`10 题 × 120s = 20:00` 与详情页时长完全吻合 | **单题 120 秒**，整场时长自动推导（02-3.4 / 02-4.5） |
| 2 | Quiz 详情「10 questions」与答题页「Q:1/8」冲突 | 两处确实不一致（源站缺陷） | 定义为「10 关独立题库，每关 8 题，详情页显示本关题数」 |
| 3 | `Spots Filled` 可能是交卷人数 | `C3` 显示 `6/651`、`c1` 各卡报名数 ≥ 0 且与参与人数独立 | **报名人数**（需求方 L3 确认） |
| 4 | 关卡片与列表可能无「关卡」入口 | `B1` 有独立 `Levels` Tab | 关卡作为详情页第二个 Tab |
| 5 | 报名后按钮文案 | `C3` 为 `Play Now`，原截图另一处为 `Start Playing` | 统一为 `Play Now` |
| 6 | 结果页是否有逐题解析 | `B5-Preview Answers` 证实有独立回顾页 | 结果页仅统计 + 入口，回顾独立路由 |
| 7 | 报名是否校验余额 | `B2` 显示余额 457 < 报名费 600 仍可点 | 判定为源站缺陷，我方**必须校验并置灰** |
| 8 | 富文本是否已转义 | `B1` 描述区直接输出 `<p>` 标签 | 前台按白名单渲染，禁止裸输出 |

## 3. 技术方案（已确认）

| 项 | 决策 |
| --- | --- |
| 后台 | Next.js 15 + shadcn-admin 二次开发（Python/Django 为备选） |
| 服务端 | NestJS + Prisma + PostgreSQL + Redis（四端共用一套 API） |
| 用户端 PC | Next.js 15（文章/详情走 SSR，利于 SEO） |
| H5 + 小程序 | uni-app（Vue3 + TS），一套代码两端 |
| 支付 | 微信支付 v3 + 支付宝（PC 扫码 / H5 跳转 / 小程序 JSAPI） |
| 提现 | 微信零钱（商家转账）/ 支付宝 / 银行卡（人工） |
| 多语言 | i18n（默认简体中文 + 英文），语言包共用 |
| 后台数量 | 一个 |

详见 `05-技术选型与架构方案.md`。
