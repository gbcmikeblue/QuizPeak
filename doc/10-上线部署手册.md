# 知巅 QuizPeak 上线部署手册

> 适用版本：2026-10-23（22 次提交后的完整功能版）
> 目标：把当前代码变成「可部署、可备份、可观测、可回滚」的生产服务。

## 1. 架构与端口

```
                ┌──────────── nginx (80/443) ────────────┐
   用户          │  quizpeak.example.com  → web:3000      │
  ──────────►    │  admin.quizpeak.example.com → admin:3001│
                │  两者 /api/  → api:8080                 │
                └───────────────────┬────────────────────┘
                                    │
                         api:8080 (NestJS) ──► postgres:5432
                                    └──► /app/uploads（volume）
```

| 服务 | 容器内端口 | 对外 | 说明 |
| --- | --- | --- | --- |
| web | 3000 | 经 nginx | 用户端（Next standalone） |
| admin | 3001 | 经 nginx | 运营后台（Next standalone） |
| api | 8080 | 经 nginx `/api` | NestJS，启动时自动 `prisma migrate deploy` |
| postgres | 5432 | 不暴露 | 数据卷 `pgdata` |
| nginx | 80/443 | 是 | 反向代理 + TLS 终止 |

## 2. 环境变量清单

复制模板：

```bash
cp .env.production.example .env.production
```

### 2.1 必填

| 变量 | 示例 | 说明 / 风险 |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://quizpeak:pwd@postgres:5432/quizpeak?schema=public` | 容器内用服务名 `postgres`；密码与 `POSTGRES_PASSWORD` 一致 |
| `POSTGRES_PASSWORD` | 随机串 | **必须改**，默认值会被扫描 |
| `JWT_SECRET` | `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` | 泄露 = 任何人可伪造登录态，务必 ≥32 字节随机 |
| `SMS_DEV_MODE` | `false` | **生产必须 false**。为 true 时验证码会随接口返回并明文显示在后台「短信记录」，等于任意手机号可登录 |

### 2.2 可选（有默认值）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | 8080 | API 端口 |
| `JWT_ACCESS_EXPIRES` | 15m | 访问令牌有效期 |
| `JWT_REFRESH_EXPIRES` | 30d | 刷新令牌有效期 |
| `CORS_ORIGINS` | 空 | 跨域白名单，逗号分隔；同域反代可留空 |
| `SMS_PROVIDER` | console | 接阿里云改 `aliyun`，并补 `SMS_ACCESS_KEY_ID` 等四项 |
| `NEXT_PUBLIC_API_BASE` | `/api` | **构建期变量**，改了要重新 build 前端镜像 |

### 2.3 脚本用

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `BACKUP_DIR` | `./backups` | 备份输出目录 |
| `BACKUP_RETENTION_DAYS` | 7 | 保留天数 |
| `ALERT_WEBHOOK_URL` | 空 | 钉钉/飞书/企微机器人，留空则只写日志 |

## 3. 首次部署

```bash
# 1) 拉代码
git clone git@github.com:gbcmikeblue/QuizPeak.git /opt/quizpeak
cd /opt/quizpeak

# 2) 配置环境变量
cp .env.production.example .env.production
vi .env.production          # 至少改 POSTGRES_PASSWORD / JWT_SECRET / SMS_DEV_MODE=false

# 3) 准备证书目录（没有证书先空着，nginx 只跑 80）
mkdir -p deploy/certs uploads backups

# 4) 构建并启动（首次约 5~10 分钟，主要是 npm ci + next build）
docker compose build
docker compose up -d

# 5) 首次初始化数据（管理员、分类、积分规则、示例题库/徽章/文章）
docker compose exec api npx prisma db seed

# 6) 验证
docker compose ps
curl -s localhost/api/health
```

访问：

| 地址 | 说明 |
| --- | --- |
| `http://<服务器IP>/` | 用户端 |
| `http://admin.<域名>/login` | 后台（默认 `admin` / `Admin@123456`，**登录后立刻改密**） |

> 域名未就绪时可直接用 IP 访问 80 端口；nginx 配置里 `server_name _` 已兜底。

## 4. HTTPS

### 方案 A：certbot 申请（推荐）

```bash
# 1) 先确保 80 端口可访问且 DNS 已解析
docker run --rm -v "$PWD/deploy/certs:/etc/letsencrypt" \
  -v "$PWD/deploy/certbot-www:/var/www/certbot" \
  certbot/certbot certonly --webroot -w /var/www/certbot \
  -d quizpeak.example.com -d admin.quizpeak.example.com \
  --email ops@example.com --agree-tos --no-eff-email

# 2) 复制证书到挂载目录
cp deploy/certs/live/quizpeak.example.com/fullchain.pem deploy/certs/fullchain.pem
cp deploy/certs/live/quizpeak.example.com/privkey.pem   deploy/certs/privkey.pem

# 3) 打开 nginx 配置里的 443 段，重载
docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload
```

续期（crontab）：

```bash
0 4 * * 1 docker run --rm -v /opt/quizpeak/deploy/certs:/etc/letsencrypt -v /opt/quizpeak/deploy/certbot-www:/var/www/certbot certbot/certbot renew --quiet && docker compose -f /opt/quizpeak/docker-compose.yml exec nginx nginx -s reload
```

### 方案 B：云负载均衡 / CDN 终止 TLS

SSL 证书挂在 SLB 或 CDN 上，回源到本机 80 端口；本机 nginx 保持现状即可，无需 443。

### 强制 HTTPS

证书就绪后，把 80 段改为：

```nginx
server {
    listen 80;
    server_name quizpeak.example.com admin.quizpeak.example.com;
    location /.well-known/acme-challenge/ { root /var/www/certbot; }
    location / { return 301 https://$host$request_uri; }
}
```

## 5. 备份与恢复

### 5.1 备份

```bash
chmod +x deploy/backup.sh
./deploy/backup.sh
```

产出：`backups/db-YYYYmmdd-HHMMSS.sql.gz`（含 `--clean --if-exists`，可直接覆盖恢复）+ `uploads-*.tar.gz`。

crontab（每天 3 点）：

```bash
0 3 * * * cd /opt/quizpeak && ./deploy/backup.sh >> logs/backup.log 2>&1
```

### 5.2 恢复

```bash
# 数据库
gunzip -c backups/db-20261023-030000.sql.gz | docker compose exec -T postgres psql -U quizpeak -d quizpeak

# 上传文件
docker compose exec -T api tar -xzf - -C /app < backups/uploads-20261023-030000.tar.gz
```

### 5.3 异地保存（建议）

```bash
# 阿里云 OSS 示例（需安装 ossutil 并配置）
ossutil cp -r backups/ oss://your-bucket/quizpeak-backup/ --update
```

## 6. 日志

| 目标 | 命令 / 方式 |
| --- | --- |
| API 实时日志 | `docker compose logs -f api` |
| 后台/用户端 | `docker compose logs -f admin web` |
| nginx 访问日志 | `docker compose logs -f nginx`，或挂载 `/var/log/nginx` 到宿主机 |
| 日志轮转 | compose 默认 json-file，建议改成限制大小（见下） |

限制单容器日志体积（`docker-compose.yml` 每个服务可加）：

```yaml
    logging:
      driver: json-file
      options:
        max-size: '50m'
        max-file: '5'
```

应用侧已有日志点：

- API 启动、异常（`ApiExceptionFilter` 统一记录 `Unhandled error METHOD URL`）
- 竞赛自动结算（每 5 分钟扫描，日志含参与人数与发奖人次）
- 短信发送（`[SMS:场景] 手机号 -> 验证码`，**生产建议在接入真实通道后移除验证码明文**）

## 7. 告警

```bash
chmod +x deploy/healthcheck.sh
ALERT_WEBHOOK_URL='https://oapi.dingtalk.com/robot/send?access_token=xxx' ./deploy/healthcheck.sh
```

检查项：API 健康（含 DB 状态）、用户端、后台登录页、磁盘使用率（≥85% 告警）。

crontab（每分钟）：

```bash
* * * * * cd /opt/quizpeak && ./deploy/healthcheck.sh >> logs/health.log 2>&1
```

告警内容越简洁越好，示例：

```
[知巅 QuizPeak 告警] 2026-10-23 10:12:01
✖ API 健康 502（期望 200） http://localhost/api/health
✔ 用户端 200
✔ 后台登录 200
✖ 数据库状态 down
✔ 磁盘 61%
```

## 8. 上线检查清单

按顺序勾选，任一项不通过不要上线：

- [ ] `SMS_DEV_MODE=false`，后台「短信记录」中验证码已脱敏
- [ ] `JWT_SECRET` 已换成随机 48 字节，非默认值
- [ ] `POSTGRES_PASSWORD` 已改，数据库端口未对公网暴露
- [ ] 管理员密码已从 `Admin@123456` 改掉（系统设置 → 站点与规则页底部）
- [ ] `docker compose ps` 四个服务均 running，`/api/health` 返回 `{"status":"ok","db":"up"}`
- [ ] 用户端首页、登录、答题、竞赛、积分、排行榜、个人中心逐页点通
- [ ] 后台题库、竞赛、用户、工单、审计、设置逐页点通
- [ ] 图片上传成功，重启容器后图片仍可访问（验证 volume 生效）
- [ ] 备份脚本跑通，能从备份恢复到空库（至少演练一次）
- [ ] 健康检查脚本 + crontab 已配置，告警群能收到消息
- [ ] HTTPS 生效，HTTP 已 301 跳转
- [ ] `doc/08-测试文档.md` 的 60+ 用例抽测通过
- [ ] 已确认积分不可兑现的合规表述出现在 About / 隐私政策

## 9. 回滚

镜像与代码：

```bash
cd /opt/quizpeak
git log --oneline -5          # 找到上一个稳定提交
git checkout <commit>
docker compose build
docker compose up -d
```

数据库回滚（迁移不可逆时）：

```bash
gunzip -c backups/db-<稳定版本时间>.sql.gz | docker compose exec -T postgres psql -U quizpeak -d quizpeak
```

> 迁移文件都在 `server/prisma/migrations/`，上线前请确认已备份，且新迁移是**向后兼容**的（加字段/加表优先，避免直接删列）。

## 10. 已知限制（上线前需知）

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 图片存储 | 本地 `uploads/` volume | 多实例或大流量时换 OSS/COS，接口返回结构不变 |
| 通知 | 无实时推送，切页/刷新才拉取 | 后续接 SSE |
| 管理员 | 单角色（SUPER_ADMIN），无权限矩阵 | 多人运营前补角色 |
| 限流 | 仅验证码有 60s/日限次 | 建议在 nginx 层加 `limit_req` |
| 竞赛结算 | 每 5 分钟扫描 + 手动兜底 | 精度要求高时改为精确定时任务 |
| 日志 | stdout + docker 收集 | 接 Loki/ELK 做检索 |

## 11. 常用运维命令

```bash
docker compose ps                          # 状态
docker compose logs -f api                 # API 日志
docker compose restart api                 # 重启 API
docker compose exec api npx prisma migrate status   # 迁移状态
docker compose exec postgres psql -U quizpeak -d quizpeak -c '\dt'  # 表清单
docker stats                               # 资源占用
du -sh backups uploads                     # 磁盘占用
```
