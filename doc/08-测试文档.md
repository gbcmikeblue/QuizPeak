# 知巅 QuizPeak 测试文档

> 适用范围：当前已实现功能（登录、答题、竞赛、积分、排行榜、个人中心、收藏徽章、文章、工单、通知、小游戏、后台管理）。
> 版本：2026-10-23

## 1. 测试环境

| 项 | 值 |
| --- | --- |
| 用户端 | http://localhost:3000 |
| 运营后台 | http://localhost:3001 |
| API | http://localhost:8080/api |
| 数据库 | 本地嵌入式 PostgreSQL，端口 5433，数据在 `.dev/pgdata` |
| 短信 | 开发模式（`SMS_DEV_MODE=true`），验证码由接口回传并自动填入登录页，也可在后台「短信记录」查看 |

启动顺序（四个终端）：

```bash
npm run db:local                    # 5433
npm run dev:server                  # 8080
npm run dev:admin                   # 3001
npm run dev -w @quizpeak/web-pc     # 3000
```

## 5. 浏览器 E2E 操作路径

1. **主链路**：`/login`（13700002222）→ `/quizzes` → 题库详情 → 解锁 → Level 1 答题 → 交卷 → 结果页 → `/points` 签到 → `/leaderboard` 点赞 → `/me` 查看记录与徽章。
2. **竞赛**：`/contests` → 详情 → 报名 → 开始答题 → 交卷（提示「待结算」）→ 后台「竞赛管理」点结算 → 用户收到结算通知。
3. **工单**：`/support` 新建 → 后台 `/dashboard/tickets` 回复并改状态 → 用户 `/notifications` 看到通知。
4. **小游戏**：`/games` → 选 Wordling Min → 输入 3 字母 → 色块反馈 → 猜中得积分。
5. **后台造题**：`/dashboard/quizzes/new` → 生成关卡 → 加题 → 发布 → 用户端立即可见。

## 7. 已知限制

1. 短信为开发模式，未接真实通道（`SmsService.send` 里 TODO）。
2. 竞赛结算为「每 5 分钟扫描 + 后台手动」，没有精确到秒的定时器。
3. 小游戏仅 Wordling 三个变体，Hexling 未实现；奖励积分项 `points.game_reward` 未在后台表单暴露。
4. 图片存本地 `server/uploads/`，多实例部署需换对象存储；无孤儿文件清理。
5. 通知无实时推送（需刷新或切换路由后拉取）。
6. 后台只有单一 SUPER_ADMIN 角色，无操作审计日志。
7. 未做接口限流（验证码除外）与压测。
