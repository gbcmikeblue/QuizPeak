# 后台角色与权限矩阵

> 实现位置：`server/src/common/admin-permissions.ts`（唯一来源）+ `AdminAuthGuard`（统一校验）
> 前端：`admin/components/sidebar.tsx`（菜单过滤）、`admin/app/dashboard/admins/page.tsx`（账号管理与矩阵展示）

## 1. 四个角色

| 角色码 | 名称 | 定位 |
| --- | --- | --- |
| `SUPER_ADMIN` | 超级管理员 | 全部权限，可管理其他管理员 |
| `OPERATOR` | 运营 | 题库、竞赛、活动、内容、搜索记录、短信、用户查询 |
| `SUPPORT` | 客服 | 工单、用户查询、搜索记录、短信记录 |
| `FINANCE` | 积分运营 | 积分流水、积分任务、用户调积分、操作审计 |

## 3. 权限点 ↔ 接口路径

校验在 `AdminAuthGuard` 内按**路径前缀**执行，新接口只要落在已有前缀下就自动受控：

| 路径前缀 | 权限 |
| --- | --- |
| `/admin/auth/*` | 只校验登录态（不额外限权） |
| `/admin/dashboard` | dashboard |
| `/admin/quizzes`、`/admin/questions`、`/admin/categories`、`/admin/upload` | quizzes |
| `/admin/contests` | contests |
| `/admin/users`、`/admin/reveal-phone` | users |
| `/admin/point-transactions` | points |
| `/admin/activities` | tasks |
| `/admin/tickets` | tickets |
| `/admin/sms` | sms |
| `/admin/articles` | content |
| `/admin/search-history` | search |
| `/admin/audit-logs` | audit |
| `/admin/config`（读 `points.*` 例外，见下）、`/admin/badges`、`/admin/avatars` | system |
| `/admin/admins` | admins |

无匹配前缀时不做额外校验（默认放行，所以新模块务必补上映射）。

### 配置读取的 prefix 级限制

「积分任务」页需要读取 9 项积分数值（`points.*`），但运营没有「系统设置」权限。为避免因此打不开页面，`/admin/config` 做了细化：

| 角色 | `GET /admin/config?prefix=points.` | `GET /admin/config?prefix=site.`（或 `rule.`、无 prefix） | `PUT /admin/config` |
| --- | :-: | :-: | :-: |
| 超级管理员 | ✅ | ✅ | ✅ |
| 运营（有 tasks 无 system） | ✅ 200 | ❌ 403 | ❌ 403 |
| 客服 / 积分运营 | ❌ 403（无 tasks 也无 system） | ❌ 403 | ❌ 403 |

前端配套：运营打开积分任务页时，9 个数值输入框置灰、保存按钮禁用，并提示「当前角色仅可查看数值，修改需要系统设置权限」；活动区块仍可正常读写。

## 4. 前端表现

1. 登录响应与 `/admin/auth/me` 返回 `role`、`roleLabel`、`permissions[]`，存在 localStorage
2. 侧边栏按 `permissions` 过滤菜单与子菜单；无权限的入口**不显示**
3. 直接输入 URL 访问无权限页面：接口返回 `403 当前角色无「XX」权限，请联系超级管理员`，页面顶部红色提示
4. 侧边栏底部显示当前角色名

## 5. 账号管理（仅超级管理员）

页面：`/dashboard/admins`

| 操作 | 说明 |
| --- | --- |
| 新建 | 用户名 + 显示名称 + 初始密码（≥8 位）+ 角色 |
| 改角色 | 行内下拉，立即生效（对方重新登录或刷新后菜单变化） |
| 停用 / 启用 | 停用后该账号登录返回 `401 账号已停用` |
| 重置密码 | 弹框输入新密码，服务端 bcrypt 存储 |
| 查看矩阵 | 页面底部只读展示四个角色的权限点 |

安全约束（服务端强制）：

- 不能停用当前登录的账号
- 不能修改自己的角色
- 系统至少保留一个**启用状态**的超级管理员

## 6. 新增角色或权限点

改两处即可：

1. `admin-permissions.ts`
   - 在 `Permission` 类型与 `PERMISSION_LABELS` 加权限点
   - 在 `ROLE_PERMISSIONS` 给角色分配
   - 若对应新接口路径，在 `PATH_RULES` 加映射
2. `admin/components/sidebar.tsx`
   - 菜单项的 `perm` 字段改为新权限点

> 修改后需重启 API（`npx pm2 restart api`）并重新构建后台（`npm run build -w @quizpeak/admin && npx pm2 restart admin`）。

## 8. 已知限制

| 项 | 说明 |
| --- | --- |
| 令牌不随角色立即失效 | 改角色后，对方手上的 access token 仍有效到过期（默认 15m）；权限按请求实时读库判断，因此**权限本身立即生效**，只是前端菜单要刷新才变 |
| 无字段级权限 | 目前是接口级；例如「用户管理」里查看手机号与封禁共用同一权限点 |
| 无审批流 | 管理员创建/停用即时生效，靠审计与人工复核 |
